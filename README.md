# 矿石配料反推与异常定位

由成品四项元素含量反推三种原矿的质量占比，定位配料异常。技术栈：FastAPI + SQLite
（标准库 `sqlite3`）+ Jinja2 页面，可实际用 Docker Compose 启动。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>。数据库落在名为 `ore-data` 的 Docker 卷中，
容器重建后数据仍在。`docker compose down -v` 会连数据一起删除。

### 本地直接运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

默认数据库路径为 `data/app.db`，可用环境变量 `ORE_DB_PATH` 覆盖。

## 页面操作

1. **上传输入**：选择“基准 CSV”（三种原矿 × 四项元素）和/或“成品 CSV”
   （样本编号 × 四项元素）。每次上传都会**整版替换**所选的输入；未选择的输入保持不变。
   两类文件可以一次提交，此时在同一事务里一起替换。
2. **计算占比**：点击按钮，对当前两份输入中的每个样本求解。报告发布后页面显示
   占比、预测值、残差与 SSE。
3. **报告状态**：任一输入被替换后，上一份报告立即显示“已过期”，但仍可查看，
   并分别标明基准/成品哪一侧与当前输入不一致。
4. **报告对照（样本级影响清单）**：在第 4 区选择一份**旧报告**和**当前最新、
   未过期的报告**，生成并保存样本级影响清单——按样本编号列出新增、移除，以及
   实测值、占比（或非唯一可达区间）、预测值、残差与 SSE 的精确变化与归因；
   已保存清单可随时查看或导出 CSV，详见下文。
5. **导出**：报告与影响清单都可导出 CSV；报告 CSV 的占比含 min/max 列，输入
   也可以导出为 CSV。

示例文件位于 `sample_data/baseline.csv` 和 `sample_data/samples.csv`。

### CSV 格式

基准 `baseline.csv`（第一列表头任意，但必须恰好 3 行原矿、4 个元素列）：

```csv
ore,Fe,SiO2,Al2O3,CaO
A,62.30,3.90,2.10,1.20
B,68.50,2.50,1.10,0.80
C,55.20,6.20,3.40,2.10
```

成品 `samples.csv`（第一列表头任意，样本编号不能重复，元素列按名称与基准匹配）：

```csv
sample_id,Fe,SiO2,Al2O3,CaO
S-1001,62.74,3.71,2.02,1.13
```

校验规则：UTF-8 编码（接受 BOM）、空行忽略；每格必须是**有限非负数**
（支持 `1.5`、`1e-3` 这类十进制/科学计数法，拒绝 `nan`/`inf`/负数/其它字符）；
绝对值须在 `1e-100` 与 `1e100` 之间（防止异常输入把精确整数运算拖垮）；
样本编号必须非空且不重复；列数必须一致；单文件 ≤ 5 MB，成品最多 2000 个样本。

任何一行不合法都会**整体拒绝**该文件，原有输入与旧报告不受影响。

## 计算模型与“无法唯一确定”

对每个样本，令 `A` 为 4×3 的基准矩阵（列为三种原矿），`y` 为四项实测含量，
求解

```
min  || A w - y ||²   s.t.  w ≥ 0,  w₁ + w₂ + w₃ = 1
```

这是一个带单纯形约束的最小二乘问题。实现上枚举单纯形的 7 个非空面（3 个顶点、
3 条边、1 个三角形），在每个面的相对内部精确求出驻点集合，再比较各面 SSE 取全局最小。
所有中间运算使用 `fractions.Fraction` **精确有理数**：

- 比例的“是否唯一”是**精确判定**，不是浮点阈值判断；
- 不存在“两个同样最优解因舍入误差被当成一个”的情况；
- 唯一解时输出精确比例（如 `19229/20780`），显示时再转成小数。

当最优解不唯一（例如两种原矿元素含量完全相同、或基准矩阵秩小于 3）时，报告
**不会任取一组**：占比、预测值与残差都以该最优解集合的精确可达区间（min ~ max）
呈现，并标记“无法唯一确定”。CSV 导出同样如此——非唯一样本的 `*_weight` 单元格
留空，只给 `*_weight_min` / `*_weight_max`。

## 上传与计算交错时的发布规则

- 上传：整份文件解析并校验通过后才进入数据库事务；两类输入在同一事务内替换，
  并且 `input_versions` 上有“每个 kind 只能有一个 `is_current`”的唯一索引。
- 计算：开始时用**同一读事务**取出两份当前输入的快照（含版本号），整个计算只依赖
  该快照。
- 发布：`BEGIN IMMEDIATE` 事务内先复查“这两个版本号是否仍是当前版本”，再插入报告。
  若期间有输入被上传替换，则**丢弃**本次结果并提示重新计算，绝不发布与当前输入
  不符或混合新旧输入的报告。
- 报告与版本：报告只存版本号；页面每次读取时用当前版本号对比，得出是否过期。
  因此“过期”状态永远是实际状态，不会因为漏改标志位而错误。
- 写入失败（磁盘/数据库错误）时页面提示，旧报告与其过期状态照常可看。

## 报告对照与样本级影响清单

### 选报告与对齐规则

- 新侧只能选**当前最新且未过期**的报告；旧侧可以是任何更早的报告（包括已过期的）。
  最新报告过期时，生成按钮禁用并提示先重新计算。
- 样本按**编号**对齐：新报告独有的编号记为“新增”，旧报告独有的记为“移除”，
  两侧都有的为“共有”，逐条给实测值、占比、预测值、残差、SSE 的旧值→新值与差值。
- 原矿与元素按**名称**对齐（与列顺序无关）；两份报告的原矿名称集合或元素名称集合
  不一致时**整体拒绝对照**，不会把不同名称的列强行配对。

### 非唯一解怎么对照

非唯一最优解没有确定占比，因此对照时也**不会任取一组数值**：占比、预测值与残差
只比较两侧的精确可达区间（min ~ max），区间不同才标记为变化。SSE 始终是确定标量，
正常参与差值比较。

### 两侧输入都变了：交叉组合与归因

当两份报告的基准、成品输入版本都不同时，系统用历史输入快照额外重算两个交叉组合：
旧基准 × 新成品（隔离成品改动）、新基准 × 旧成品（隔离基准改动），据此把每个变化
分量归入四类之一：

- **基准单侧改动 / 成品单侧改动**：只有对应一侧的隔离组合发生了变化；
- **共同影响**：两个隔离组合各自都引起了该分量变化；
- **无法归因**：该分量涉及非唯一最优解（两侧输入都在动时，区间变化无法归给某一侧）。

只有一侧输入变更时不需要交叉组合，原因唯一，直接标记为对应侧的单侧改动；新增/移除
样本本身由成品输入决定，归为成品单侧改动。

### 生成交错与持久化规则

- 影响清单在 `BEGIN IMMEDIATE` 事务内复查三件事：两份报告仍存在、新侧仍是
  **最新**报告、新侧的两个输入版本**仍为当前版本**（未过期）。任一条件不满足就
  丢弃本次结果，绝不发布针对旧目标的清单。
- `impact_lists` 表对“旧报告 × 新报告”有序报告对有唯一索引：同一报告对重复生成
  会在单条 UPDATE 内替换，写入失败时原清单保留；不同报告对各自独立保存。
- 已保存清单是生成时刻的完整快照，之后输入或最新报告继续变化也不影响其内容，
  始终可按编号查看、导出。

## 已知限制

- 计算是纯 Python 精确有理数运算，2000 个样本约 7–8 秒；页面显示前 500 行，
  其余通过 CSV 导出查看。
- 页面显示的小数经四舍五入（默认 8 位，占比为百分比）；精确值保存在数据库/JSON
  接口中（以 `分子/分母` 形式给出）。量级极端的值在网页上以科学计数法显示。
- `/api/latest` 返回完整报告（含全部样本的精确值）；2000 个样本时响应约 1.7 MB。
- 仅支持“三种原矿 / 四项元素”的固定规模，与题目要求一致。
- 单进程内用线程锁串行化写操作；多 worker 部署时依赖 SQLite 自身的
  `BEGIN IMMEDIATE` 与唯一索引保证一致性（未针对多 worker 做压力验证）。
- 页面无用户认证，默认假设在内网/可信环境使用。
